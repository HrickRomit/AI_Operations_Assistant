1. Project Overview & Current State
----------------------------------
The AI Operations Assistant is a multi-module SaaS platform designed to automate repetitive operational tasks for SMBs (e.g., document Q&A, email drafting, lead scoring, and reporting). 

Currently, the monorepo foundation is established with a running React frontend and FastAPI backend. The core Document Ingestion & Retrieval-Augmented Generation (RAG) QA pipeline is fully implemented using Google Gemini APIs and ChromaDB. Authentication and basic dashboard views are also fully operational. Other analytical modules (Email, Leads, Reports) are implemented on the frontend with temporary simulator fallbacks awaiting backend deployment.

2. Technology Stack & Core Infrastructure
----------------------------------------
* Frontend:
  - Framework: React (Vite-based setup)
  - Styling: Tailwind CSS & Vanilla CSS
  - API Client: Axios (with JWT interceptor token support)
* Backend:
  - Framework: FastAPI (Python 3)
  - Database: PostgreSQL (with SQLAlchemy ORM)
  - Vector Store: ChromaDB (PersistentClient for local vector storage)
* AI / LLM Integration:
  - Client: Google GenAI SDK (`google-genai` library)
  - Embeddings: `gemini-embedding-001` (RETRIEVAL_DOCUMENT & RETRIEVAL_QUERY tasks)
  - Chat/RAG Engine: `gemini-2.5-flash` (System instructions + temperature 0.2)
* Authentication:
  - JWT Tokens (OAuth2PasswordBearer)
  - bcrypt (Password hashing)

3. Database Schema (PostgreSQL)
-------------------------------
The following core database tables are defined and synchronized via SQLAlchemy:

* Table: `users`
  - `id`: UUID (Primary Key, autogenerated)
  - `email`: VARCHAR(255) (Unique, index)
  - `password_hash`: VARCHAR (bcrypt encrypted)
  - `business_name`: VARCHAR(255)
  - `plan`: VARCHAR(50) (default: "free")
  - `created_at`: TIMESTAMP

* Table: `documents`
  - `id`: UUID (Primary Key, autogenerated)
  - `user_id`: UUID (Foreign Key linking to `users.id`)
  - `filename`: VARCHAR (Original file name)
  - `storage_url`: VARCHAR (Local file path for file access)
  - `chunk_count`: INTEGER (Number of embedded chunks in vector store)
  - `status`: VARCHAR(50) ("processing", "ready", "error")
  - `uploaded_at`: TIMESTAMP

4. Current Backend API Endpoints
-------------------------------
The FastAPI application currently exposes and implements the following endpoints:

* Auth Endpoints (`/auth`):
  - `POST /auth/register`: Create a new user with email, password, and business name.
  - `POST /auth/login`: Authenticate credentials, returns a JWT token.
  - `GET /auth/me`: Fetch profile information of the currently authenticated user.

* Document Endpoints (`/documents`):
  - `GET /documents/`: List all uploaded files belonging to the authenticated user.
  - `POST /documents/upload`: Accepts files (PDF, DOCX, TXT), saves them, chunks, embeds, and indexes them.
  - `DELETE /documents/{doc_id}`: Removes the document from PostgreSQL and deletes all corresponding vector chunks from ChromaDB.

* Chat Endpoints (`/chat`):
  - `POST /chat/query`: Accepts natural language queries, runs vector retrieval against user-specific documents, builds context, and responds with Gemini 2.5 Flash including source citations.

5. RAG Pipeline Architecture
----------------------------
The RAG pipeline is fully functional and operates through the following stages:

* Stage 1: Document Parsing (`document_parser.py`)
  - Supports `.txt` files (UTF-8 format).
  - Supports `.pdf` files (extracted page-by-page using `pypdf`).
  - Supports `.docx` files (extracted paragraph-by-paragraph using `python-docx`).

* Stage 2: Text Chunking (`chunker.py`)
  - Cleans whitespace and splits documents using a sliding window.
  - Default chunk size: 900 characters.
  - Default overlap: 150 characters.

* Stage 3: Embedding & Vector Storage (`embedding_service.py` & `rag_service.py`)
  - Generates embeddings using Google Gemini's `gemini-embedding-001` model.
  - Stores text chunks, embeddings, and metadata (e.g., `filename`, `chunk_index`, `user_id`, `doc_id`) in ChromaDB.
  - Multi-tenancy is enforced by querying ChromaDB with a filter for `user_id`.

* Stage 4: Semantic Search & QA Generation (`chat_service.py`)
  - Embeds the user's question with task type `RETRIEVAL_QUERY`.
  - Queries ChromaDB for the top 5 most similar chunks.
  - Merges matches into a formatted context block.
  - Instructs Gemini 2.5 Flash to answer using *only* the context, outputting the answer and exact source references (filename, chunk index, context snippet) to the client.
